# Комплексный аудит и устранение ошибок в «ЭлЖур»

Полная стабилизация электронного журнала: исправление критических ошибок проверки паролей и создания новых школ, синхронизация данных всех школ для Создателя, сохранение дат журнала в облаке, адаптивный пересчёт сводной ведомости и устранение дефектов адаптивной вёрстки и тёмной темы без потери существующих функций и стилей.

### User Review & Critical Decisions

> [!IMPORTANT]
> Ниже зафиксированы подтверждённые вами решения по результатам аудита:

- **Отображение классов в журнале учителя**: В журнале учителя будут отображаться только назначенные ему классы (по нагрузке, списку классов и выданным разрешениям на замену), аналогично вкладкам расписания и домашних заданий, с понятным информационным сообщением при отсутствии назначенных классов.
- **Динамический пересчёт порогов успеваемости**: В сводной ведомости классного руководителя («Клас. рук.») пороги отличников, ударников и троечников будут автоматически масштабироваться под настроенный в школе диапазон оценок (`minGrade` — `maxGrade`), сохраняя точные классические пороги `4.5 / 3.5 / 2.5` для стандартной 5-балльной шкалы.

### 1. Overview & Core Concept

- **Что делает обновление**: Устраняет скрытые логические ошибки, блокировки сохранения пользователей и школ, потери данных при перезагрузке страницы, рассинхронизацию в режиме Создателя, а также исправляет наложения элементов на мобильных/планшетных экранах и контрастность в светлой и тёмной темах.
- **Целевая аудитория**: Все роли образовательного портала — Создатель (управление школами и глобальной базой), Директор и Администрация (расписание, нагрузка, классы, пользователи), Учителя (электронный журнал, классное руководство, ДЗ) и Ученики (дневник, оценки, рейтинг).
- **Ключевая ценность**: Абсолютная надёжность работы с базой данных Firestore, корректная валидация учётных записей, предсказуемая аналитика по любой шкале оценивания и аккуратная вёрстка на любых разрешениях экрана.

### 2. User Experience & Visual Design

- **Ключевые пользовательские сценарии**:
  1. *Управление пользователями и школами*: Администратор и Создатель могут свободно редактировать пользователей и добавлять новые школы; пароли новых директоров автоматически хешируются с солью перед отправкой в облако, а проверка уникальности связки «логин + пароль» срабатывает только при реальном совпадении пароля (`isMatch.valid`).
  2. *Глобальная панель Создателя*: При входе под ролью Создателя система подписывается на данные всех школ, корректно отображая общую статистику, глобальный рейтинг и позволяя сохранять изменения или удалять любую школу в базе.
  3. *Работа учителя в Журнале*: Добавленные вручную даты уроков в четвертях сохраняются в облачном документе школы и не пропадают после обновления страницы; нижняя панель редактирования комментария к оценке гармонично адаптируется под светлую и тёмную темы.
  4. *Информационное окно до входа*: При нажатии на логотип «ЭлЖур» на экране авторизации сразу загружаются актуальные данные холста «Информация об ЭлЖуре» и пользовательские шрифты из основной школы.
- **Визуальная система и исправления вёрстки**:
  - *Сохранение фирменного стиля*: Все существующие цветовые акценты, анимации, карточки и типографика полностью сохраняются.
  - *Редактор расписания*: Шапка карточки учебного дня переводится на адаптивную флекс-сетку (`flex-wrap`), чтобы кнопки «Настройки дня» и «Удалить день» никогда не перекрывали поле выбора даты и дня недели на планшетах и смартфонах.
  - *Полосы прокрутки и контрастность*: Кастомные скроллбары (`.custom-scrollbar`) получают поддержку тёмной темы (`.dark`), устраняя яркие белые полосы внутри тёмных таблиц и выпадающих списков, а числа в таблицах и ведомостях выравниваются табличными цифрами (`tabular-nums`).

### 3. Key Product Decisions & Trade-Offs

- **Решение 1: Корректная криптографическая валидация при создании школ и пользователей**
  - *Выбранный подход*: Использование булева результата `verifyUserPasswordDetailed(...).valid` при проверке дубликатов паролей и обязательное хеширование пароля директора через `generateSalt()` + `hashPassword()` при создании новой школы.
  - *Почему*: Правила безопасности Firestore запрещают сохранение паролей в открытом виде (`hasNoPlaintextPassword()`), а проверка самого объекта промиса/результата без поля `.valid` всегда возвращала `true`, блокируя работу администратора.
- **Решение 2: Облачное хранение пользовательских дат четвертей и мульти-школьная синхронизация**
  - *Выбранный подход*: Сохранение структуры дат четвертей (`quarters`) внутри документа школы в Firestore и мульти-подписка на коллекцию школ для роли `creator`.
  - *Почему*: Позволяет учителям видеть добавленные столбцы дат на любом устройстве, а Создателю — управлять всеми школами и пользователями в реальном времени без перезаписи данных только первой школы.
- **Решение 3: Пропорциональные пороги успеваемости в сводной ведомости**
  - *Выбранный подход*: Расчёт порогов «Отличник», «Ударник» и «Троечник» пропорционально диапазону `[minGrade, maxGrade]` школы (при стандартной шкале 2–5 пороги остаются ровно `4.5`, `3.5` и `2.5`).
  - *Почему*: Обеспечивает точную сводку классного руководителя при переходе школы на 10-балльную или 100-балльную систему оценивания.

### 4. Technical Architecture & Data Strategy *(Technical Reference)*

- **Архитектура синхронизации и компонентов**:
```
┌─────────────────────────────────────────────────────────────────────────┐
│                        Экран входа и Авторизация                        │
│  • Предзагрузка публичной инфо-панели («Инфо ЭлЖур») и шрифтов школы    │
│  • Проверка логина/пароля (PBKDF2 / SHA-256) + привязка authUidMap      │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                 Облачный слой синхронизации (Firestore)                 │
│  ┌───────────────────────────┐         ┌─────────────────────────────┐  │
│  │ Обычные роли (По школе)   │         │ Роль Создателя (Все школы)  │  │
│  │ • Подписка на свою школу  │         │ • Подписка на все школы     │  │
│  │ • Сохранение расписания,  │         │ • Создание/удаление школ    │  │
│  │   оценок, четвертей и ДЗ  │         │ • Кросс-школьное сохранение │  │
│  └─────────────┬─────────────┘         └──────────────┬──────────────┘  │
└────────────────┼──────────────────────────────────────┼─────────────────┘
                 │                                      │
                 ▼                                      ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                    Пользовательские модули и панели                     │
│  ┌────────────────────┐  ┌─────────────────────┐  ┌──────────────────┐  │
│  │ Администрирование  │  │ Журнал и Клас. рук. │  │ Расписание и UI  │  │
│  │ • Валидация .valid │  │ • Только свои классы│  │ • Адаптивная     │  │
│  │ • Хеширование при  │  │ • Сохранение дат    │  │   шапка дня      │  │
│  │   создании школы   │  │ • Динамический GPA  │  │ • Dark скроллбар │  │

└─────────────────────────────────────────────────────────────────────────┘
```

- **Модель данных и состояние**:
  - В документ школы (`schools/{schoolId}`) добавляется сохранение и чтение поля `quarters` (пользовательские даты уроков по четвертям), чтобы таблица журнала не сбрасывала добавленные колонки при перезагрузке.
  - В публичное чтение документа основной школы (`school_1`) допускается загрузка метаданных оформления и информационного холста (`eljurInfo`, `customFonts`) для отображения модального окна «Информация об ЭлЖуре» на экране входа.
  - При удалении школы Создателем выполняется удаление документа школы в Firestore и связанных с ней учётных записей.
- **Интерактивные обработчики и состояния**:
  - *Пользователи и Школы*: Исправление условия `if (isMatch.valid)` при проверке занятости пароля; асинхронное хеширование пароля директора при создании школы; маршрутизация сохранения в `saveSchoolState` по `schoolId` всех затронутых школ.
  - *Журнал учителя*: Фильтрация `myClasses` строго по назначенным учителю классам (`u.classes`, `teacherAssignments`, `substitutionPermissions`); пустое состояние с подсказкой, если классов ещё нет; адаптивное оформление нижней панели деталей оценки для светлой и тёмной темы.
  - *Сводная ведомость («Клас. рук.»)*: Вычисление порогов отличников (`min + 0.8333 * range`), хорошистов (`min + 0.5 * range`) и удовлетворительной успеваемости (`min + 0.1667 * range`), что даёт ровно `4.5 / 3.5 / 2.5` на 5-балльной шкале и корректные значения на 10/100-балльной шкале.
